## 1. Назначение плагина

**CodeMetrics** — расширение для Visual Studio Code, которое анализирует
исходный код текущего открытого файла и отображает его метрики в боковой
панели редактора.

Метрики — это числовые характеристики кода:

- сколько в файле строк (всего / кода / комментариев / пустых);
- сколько найдено функций, циклов, условий;
- какова максимальная глубина вложенности блоков `{ }`;
- как часто встречаются ключевые слова (`if`, `for`, `return`, `class` и др.).

Плагин работает в реальном времени: при любом изменении файла панель
автоматически пересчитывает метрики.

**Задача лабораторной работы:** научиться разрабатывать и подключать плагин
к IDE, изучить её архитектуру с точки зрения расширяемости, использовать
логику и структуры данных (не только подстановку сниппетов).

## 2. Архитектура плагина

Плагин построен по принципу **разделения ответственности**. Четыре слоя
отвечают за разные задачи и не смешивают их:

| Слой | Задача | Функции и сущности |
|---|---|---|
| **Точка входа** | Регистрирует команду, подписывается на события | `activate()`, `deactivate()` |
| **Анализ** | Извлекает метрики из текста | `analyzeCode()` |
| **Представление** | Формирует HTML-разметку | `buildHtml()` |
| **Отображение** | Управляет webview-панелью | `updatePanel()`, `panel` |

**Почему так:** каждый слой можно менять независимо. Например, чтобы
добавить новую метрику, достаточно изменить только `analyzeCode()` и
`buildHtml()`. Логика работы с VS Code API (слой «Отображение») при этом
не трогается.

**Не используются глобальные переменные** (кроме одной — `panel`, она
необходима для хранения ссылки на webview между вызовами). Все данные
передаются через аргументы и объект `Metrics`.

## 5. Интерфейс `Metrics`

```typescript
interface Metrics {
    lines: number;                     // всего строк в файле
    codeLines: number;                 // строк с реальным кодом
    commentLines: number;              // строк-комментариев
    blankLines: number;                // пустых строк
    functions: number;                 // количество функций (оценка)
    loops: number;                     // количество циклов
    conditionals: number;              // количество условий
    maxDepth: number;                  // максимальная вложенность { }
    keywords: Map<string, number>;     // частота ключевых слов
}
```

**Назначение:** единый контейнер результата анализа. Одна функция
(`analyzeCode`) его создаёт и заполняет, другая (`buildHtml`) — читает
и превращает в HTML. Такой подход называется «передача по значению» и
исключает случайное изменение данных в другой части программы.

**Поля подробнее:**

| Поле | Тип | Что означает |
|---|---|---|
| `lines` | `number` | Общая длина файла в строках |
| `codeLines` | `number` | Строки, где есть код (не пустые и не комментарии) |
| `commentLines` | `number` | Строки, начинающиеся с `//`, `#`, `/*` или `*` |
| `blankLines` | `number` | Строки, состоящие только из пробелов или пустые |
| `functions` | `number` | Найдены `function`, `def`, `=>`, `void`, `public` и т.п. |
| `loops` | `number` | Найдены `for`, `while`, `do` |
| `conditionals` | `number` | Найдены `if`, `else`, `switch`, `case` |
| `maxDepth` | `number` | Максимум одновременно открытых `{` |
| `keywords` | `Map<string, number>` | Слово → сколько раз встретилось |

## 6. Функция `analyzeCode`

```typescript
function analyzeCode(text: string): Metrics
```

### 6.1. Назначение

Главная функция анализа. Принимает **полный текст файла** как одну строку,
возвращает заполненный объект `Metrics`.

### 6.2. Параметры

| Имя | Тип | Описание |
|---|---|---|
| `text` | `string` | Содержимое всего файла |

### 6.3. Возвращаемое значение

Объект `Metrics` со всеми посчитанными метриками.

### 6.4. Алгоритм работы

**Шаг 1. Разбить текст на строки.**

```typescript
const lines = text.split(/\r?\n/);
```

Регулярное выражение `\r?\n` корректно работает и с Unix-переводами
строк (`\n`), и с Windows (`\r\n`). Это важно, потому что файлы могут
быть созданы в разных ОС.

**Шаг 2. Инициализировать счётчики и структуры.**

```typescript
const keywords = new Map<string, number>();  // частота слов
const depthStack: number[] = [];             // стек вложенности
let currentDepth = 0;
let maxDepth = 0;
let codeLines = 0, commentLines = 0, blankLines = 0;
let functions = 0, loops = 0, conditionals = 0;
```

**Шаг 3. Пройти по каждой строке.**

Для каждой строки:

**3.1. Классификация строки.**

- Если `line.trim().length === 0` → `blankLines++`, перейти к следующей.
- Если строка начинается с `//`, `#`, `/*` или `*` → `commentLines++`,
  перейти к следующей.
- Иначе → `codeLines++` и продолжить обработку.

**3.2. Подсчёт ключевых слов.**

```typescript
const words = line.match(/\b[a-zA-Z_а-яА-Я]+\b/g) || [];
for (const w of words) {
    const lower = w.toLowerCase();
    if (KEYWORDS.includes(lower)) {
        keywords.set(lower, (keywords.get(lower) || 0) + 1);
    }
}
```

`KEYWORDS` — массив: `['for', 'while', 'do', 'if', 'else', 'switch',
'case', 'return', 'function', 'def', 'class']`.

**3.3. Определение циклов, условий, функций.**

Три регулярных выражения проверяют строку:

```typescript
if (loopRegex.test(line)) loops++;
if (condRegex.test(line)) conditionals++;
if (funcRegex.test(line)) functions++;
```

**3.4. Подсчёт вложенности через стек.**

```typescript
for (const ch of line) {
    if (ch === '{') {
        currentDepth++;
        depthStack.push(currentDepth);
        if (currentDepth > maxDepth) maxDepth = currentDepth;
    } else if (ch === '}') {
        depthStack.pop();
        currentDepth = depthStack.length;
    }
}
```

**Почему стек, а не счётчик.** Просто инкрементировать `{` и декрементировать
`}` недостаточно: скобки могут быть несбалансированы (например, закрывающая
скобка появится без открывающей — тогда счётчик уйдёт в минус). Стек
позволяет корректно отслеживать состояние и не сломать логику.

**Шаг 4. Вернуть объект `Metrics`.**

```typescript
return {
    lines: lines.length,
    codeLines, commentLines, blankLines,
    functions, loops, conditionals, maxDepth,
    keywords
};
```

### 6.5. Пример

**Входные данные:**

```cpp
int main() {
    if (x > 0) {
        for (int i = 0; i < 10; i++) {
            cout << i;
        }
    }
    return 0;
}
```

**Результат:**

```typescript
{
    lines: 8,
    codeLines: 8,
    commentLines: 0,
    blankLines: 0,
    functions: 1,
    loops: 1,
    conditionals: 1,
    maxDepth: 3,
    keywords: Map {
        'int'    => 2,
        'if'     => 1,
        'for'    => 1,
        'return' => 1
    }
}
```

### 6.6. Сложность

- **По времени:** O(N), где N — общее количество символов в файле.
  Проходим по каждой строке ровно один раз.
- **По памяти:** O(L + K), где L — количество уникальных ключевых слов
  (для `Map`), K — максимальная вложенность (для стека). На практике
  оба значения малы.

## 7. Функция `buildHtml`

```typescript
function buildHtml(metrics: Metrics, fileName: string): string
```

### 7.1. Назначение

Принимает объект `Metrics` и имя файла, возвращает **готовую HTML-строку**
для отображения в webview-панели VS Code.

### 7.2. Параметры

| Имя | Тип | Описание |
|---|---|---|
| `metrics` | `Metrics` | Результат анализа |
| `fileName` | `string` | Имя файла для заголовка |

### 7.3. Возвращаемое значение

Строка с HTML-документом (включает `<style>`, `<table>` и `<ul>`).

### 7.4. Что генерируется

1. **Заголовок** `<h2>CodeMetrics: имя_файла</h2>`.
2. **Таблица метрик** `<table>` — 9 строк, каждая с названием и значением.
3. **Список ключевых слов** `<ul>` — отсортирован по убыванию частоты.

**Сортировка:**

```typescript
const kw = [...metrics.keywords.entries()]
    .sort((a, b) => b[1] - a[1])   // b[1] - a[1] — по убыванию
    .map(([word, count]) => `<li><b>${word}</b>: ${count}</li>`)
    .join('');
```

### 7.5. CSS-оформление

Внутри `<style>`:
- шрифт `sans-serif`;
- синие заголовки;
- таблица с рамками;
- список ключевых слов в две колонки (`columns: 2`).

Всё оформление вынесено в один блок, поэтому поменять внешний вид легко.

## 8. Функция `updatePanel`

```typescript
function updatePanel(editor: vscode.TextEditor): void
```

### 8.1. Назначение

Пересчитать метрики для текущего документа и обновить содержимое
webview-панели.

### 8.2. Параметры

| Имя | Тип | Описание |
|---|---|---|
| `editor` | `vscode.TextEditor` | Активный редактор VS Code |

### 8.3. Алгоритм

```typescript
if (!panel) return;                              // панель не создана
const text = editor.document.getText();          // весь текст файла
const metrics = analyzeCode(text);               // анализ
const fileName = editor.document.fileName        // имя файла
    .split(/[\\/]/).pop() || 'file';
panel.webview.html = buildHtml(metrics, fileName);
```

**Разбор имени файла:** путь разбивается по `/` или `\`, берётся последний
сегмент. Это работает и в Windows, и в Linux.

### 8.4. Когда вызывается

- **Вручную** — при выполнении команды `code-metrics.showMetrics`.
- **Автоматически** — при событии `onDidChangeTextDocument` (правка кода).
- **Автоматически** — при событии `onDidChangeActiveTextEditor`
  (переключение между файлами).

## 9. Функция `activate`

```typescript
export function activate(context: vscode.ExtensionContext): void
```

### 9.1. Назначение

Точка входа расширения. VS Code вызывает её **один раз** при активации
плагина (по триггеру из `activationEvents` в `package.json`).

### 9.2. Параметры

| Имя | Тип | Описание |
|---|---|---|
| `context` | `vscode.ExtensionContext` | Контекст расширения, хранит подписки |

### 9.3. Что делает

**1. Регистрирует команду:**

```typescript
const cmd = vscode.commands.registerCommand(
    'code-metrics.showMetrics',
    () => {
        const editor = vscode.window.activeTextEditor;
        if (!editor) {
            vscode.window.showWarningMessage('Открой файл с кодом');
            return;
        }
        if (panel) {
            panel.reveal();          // показать существующую панель
        } else {
            panel = vscode.window.createWebviewPanel(
                'codeMetrics',
                'CodeMetrics',
                vscode.ViewColumn.Beside,   // справа от редактора
                { enableScripts: false }    // JS в webview не нужен
            );
            panel.onDidDispose(() => { panel = undefined; });
        }
        updatePanel(editor);
    }
);
```

**2. Подписывается на изменение текста:**

```typescript
const onChange = vscode.workspace.onDidChangeTextDocument(e => {
    const editor = vscode.window.activeTextEditor;
    if (editor && e.document === editor.document) {
        updatePanel(editor);
    }
});
```

**3. Подписывается на смену активного редактора:**

```typescript
const onSwitch = vscode.window.onDidChangeActiveTextEditor(editor => {
    if (editor) updatePanel(editor);
});
```

**4. Регистрирует все подписки в `context.subscriptions`:**

```typescript
context.subscriptions.push(cmd, onChange, onSwitch);
```

Это гарантирует, что при выключении плагина все ресурсы будут
автоматически освобождены — не будет утечек памяти и «висящих» обработчиков.

## 11. Использованные структуры данных

### 11.1. `Map<string, number>` — частота ключевых слов

**Где используется:** `analyzeCode()`, поле `keywords`.

**Зачем:** `Map` позволяет за O(1):
- проверить, встречалось ли слово;
- получить текущее значение;
- увеличить счётчик.

**Пример:**

```typescript
keywords.set('if', (keywords.get('if') || 0) + 1);
```

**Почему не обычный объект `{}`:**
1. `Map` сохраняет порядок вставки.
2. `Map` корректно работает с любыми строковыми ключами (включая `__proto__`,
   `constructor` — у обычного объекта они вызовут проблемы).
3. У `Map` удобные методы: `entries()`, `has()`, `set()`, `get()`.

### 11.2. Стек (`number[]`) — вложенность блоков

**Где используется:** `analyzeCode()`, переменная `depthStack`.

**Зачем:** подсчёт вложенности блоков `{ }` — классическая задача на стек:

- При встрече `{` — `push` в стек, увеличить `currentDepth`.
- При встрече `}` — `pop` из стека, восстановить `currentDepth`.
- Максимум `currentDepth` за время разбора = `maxDepth`.

**Пример:**

```
Код:              Стек после строки:   currentDepth:   maxDepth:
{                 [1]                  1               1
  if (x) {        [1, 2]               2               2
    for {         [1, 2, 3]            3               3
    }             [1, 2]               2               3
  }               [1]                  1               3
}                 []                   0               3
```

Итог: `maxDepth = 3`.

**Почему не счётчик `{` минус `}`:**
При несбалансированных скобках (в строковых литералах, шаблонах и т.п.)
счётчик даст неверный результат. Стек корректно отслеживает состояние.

### 11.3. Массив строк `KEYWORDS`

**Где используется:** `analyzeCode()` для быстрой проверки, является ли
слово ключевым.

```typescript
const KEYWORDS = ['for', 'while', 'do', 'if', 'else', 'switch',
                  'case', 'return', 'function', 'def', 'class'];
```

Проверка `KEYWORDS.includes(word)` выполняется за O(N), где N — длина
списка (11 элементов). Для нашей задачи этого более чем достаточно.

### 11.4. Регулярные выражения

Хранятся в виде констант для читаемости:

```typescript
const loopRegex = /\b(for|while|do)\b/;
const condRegex = /\b(if|else|switch|case)\b/;
const funcRegex = /\b(function|def|void|int|public|private|protected)\b.*\(|=>/;
```

## 12. Использованные регулярные выражения

| Выражение | Что ищет | Пояснение |
|---|---|---|
| `/\r?\n/` | Перевод строки | `\r?` — опциональный `\r` (Windows) |
| `/\b[a-zA-Z_а-яА-Я]+\b/g` | Все слова | `\b` — граница слова, `/g` — все совпадения |
| `/\b(for\|while\|do)\b/` | Циклы | Только целые слова (не `format`) |
| `/\b(if\|else\|switch\|case)\b/` | Условия | `else if` тоже ловится |
| `/\b(function\|def\|void\|int\|...)\b.*\(/` | Функции | Слово + что-то + открывающая скобка |
| `/=>/` | Стрелочные функции | `const f = (x) => ...` |
| `/[\\/]/` | Разделитель пути | `/` в Linux, `\` в Windows |

**Про `\b`:** это граница слова. Она гарантирует, что `if` найдётся
в `if (x)`, но **не** найдётся в `shift` или `endif`.

## 13. Механизм активации и подписки на события

### 13.1. Активация через `activationEvents`

В `package.json` указано:

```json
"activationEvents": [
    "onLanguage:javascript",
    "onLanguage:typescript",
    "onLanguage:python",
    "onLanguage:java",
    "onLanguage:cpp"
]
```

Это значит: VS Code активирует расширение, **как только** пользователь
откроет файл одного из указанных языков. До этого момента код плагина
не загружается — экономия ресурсов.

### 13.2. Регистрация команды

Команда объявлена в двух местах:

- **`package.json` → `contributes.commands`** — манифест. Говорит VS Code,
  что такая команда существует и как называется в палитре.
- **`extension.ts` → `registerCommand()`** — реализация. Привязывает
  конкретную функцию к ID команды.

**Важно:** ID команды в обоих местах должен совпадать: `code-metrics.showMetrics`.

### 13.3. Подписки на события

| Событие | Когда срабатывает | Что делает |
|---|---|---|
| `onDidChangeTextDocument` | Изменился текст любого документа | Обновляет панель, если это активный документ |
| `onDidChangeActiveTextEditor` | Пользователь переключился на другой файл | Обновляет панель под новый файл |
| `onDidDispose` (у панели) | Пользователь закрыл панель | Сбрасывает ссылку `panel = undefined` |

Все подписки складываются в `context.subscriptions`. VS Code сам
освободит их при выключении плагина.

## 14. Взаимодействие с VS Code API

Плагин использует следующие части API:

| API | Где | Зачем |
|---|---|---|
| `vscode.commands.registerCommand` | `activate` | Регистрация команды |
| `vscode.window.activeTextEditor` | `activate`, `updatePanel` | Получить текущий редактор |
| `vscode.window.createWebviewPanel` | `activate` | Создать боковую панель |
| `vscode.window.showWarningMessage` | `activate` | Показать предупреждение |
| `vscode.workspace.onDidChangeTextDocument` | `activate` | Реакция на изменение текста |
| `vscode.window.onDidChangeActiveTextEditor` | `activate` | Реакция на смену файла |
| `editor.document.getText()` | `updatePanel` | Взять весь текст файла |
| `editor.document.fileName` | `updatePanel` | Взять путь файла |
| `panel.webview.html` | `updatePanel` | Установить HTML-содержимое |
| `panel.reveal()` | `activate` | Показать уже открытую панель |
| `context.subscriptions.push` | `activate` | Зарегистрировать подписки |

### 14.1. Что такое WebviewPanel

`WebviewPanel` — это встроенный в VS Code браузер. Он изолирован от
основного окна и может отображать произвольный HTML/CSS/JS. Мы
используем его для показа таблицы с метриками.

**Особенности:**
- По умолчанию JavaScript внутри webview **отключён** (`enableScripts: false`).
  Нам он не нужен — панель статичная.
- Панель можно расположить в любой колонке: `ViewColumn.Beside` —
  справа от редактора.
- Содержимое задаётся через `panel.webview.html = '<html>...'`.

### 14.2. Позиции панели

| Позиция | Где окажется |
|---|---|
| `ViewColumn.One` | Первая колонка (заменит редактор) |
| `ViewColumn.Two` | Вторая колонка |
| `ViewColumn.Beside` | Рядом с текущей колонкой (справа) |
| `ViewColumn.Active` | В активной колонке |

Мы используем `ViewColumn.Beside`, чтобы не вытеснять редактор.

## 15. Генерация HTML-документации через TypeDoc

В проект добавлен **TypeDoc** — инструмент, который автоматически
создаёт HTML-документацию из JSDoc-комментариев в исходном коде.

### 15.1. Установка

```bash
npm install --save-dev typedoc
```

### 15.2. Настройка в `package.json`

Добавь в `scripts`:

```json
"docs": "typedoc src/extension.ts --out docs"
```

### 15.3. Генерация

```bash
npm run docs
```

Или напрямую:

```bash
npx typedoc src/extension.ts --out docs
```

### 15.4. Результат

В папке `docs/` появится набор HTML-страниц:
- `index.html` — главная;
- `modules.html` — список модулей;
- `interfaces/Metrics.html` — страница интерфейса;
- `functions/analyzeCode.html` — страница функции;
- и т.д.

Эту папку можно открыть в браузере (двойной клик по `index.html`) и
использовать как полноценный справочник.

### 15.5. Что нужно для корректной генерации

В исходном коде должны быть **JSDoc-комментарии** над функциями и
интерфейсами. Пример:

```typescript
/**
 * Анализирует текст файла и возвращает метрики.
 * @param text Полный текст файла.
 * @returns Объект с метриками.
 */
function analyzeCode(text: string): Metrics { ... }
```

TypeDoc читает эти комментарии и вставляет их в сгенерированные
HTML-страницы.

## 16. Как расширять плагин

Плагин спроектирован так, чтобы его было легко дополнять.

### 16.1. Добавить новую метрику

1. Добавь поле в интерфейс `Metrics`:
   ```typescript
   interface Metrics {
       // ...
       todoCount: number;   // новое поле
   }
   ```

2. Посчитай его в `analyzeCode()`:
   ```typescript
   if (line.includes('TODO')) {
       stats.todoCount++;
   }
   ```

3. Отобрази в `buildHtml()`:
   ```html
   <tr><td>TODO-комментариев</td><td>${metrics.todoCount}</td></tr>
   ```

### 16.2. Добавить новый язык

Просто добавь его идентификатор в `activationEvents` в `package.json`:

```json
"activationEvents": [
    "onLanguage:go",
    "onLanguage:rust",
    "onLanguage:kotlin"
]
```

Никаких изменений в `extension.ts` не требуется — анализ работает с
текстом, а не с парсером конкретного языка.

### 16.3. Изменить оформление панели

Открой `buildHtml()` и отредактируй блок `<style>`. Например, чтобы
сделать тёмную тему:

```css
body {
    background: #1e1e1e;
    color: #d4d4d4;
}
```

### 16.4. Добавить экспорт метрик в JSON

Внутри обработчика команды можно добавить:

```typescript
const json = JSON.stringify(metrics, null, 2);
vscode.env.clipboard.writeText(json);
vscode.window.showInformationMessage('Метрики скопированы в буфер');
```

### 16.5. Добавить визуализацию (графики)

Замени в `createWebviewPanel` параметр `enableScripts` на `true` и
подключи любую JS-библиотеку для графиков (например, Chart.js через CDN).
Это отдельный шаг, но технически реализуемо.

## 17. Ограничения и известные особенности

### 17.1. Анализ текстовый, а не синтаксический

Плагин не использует настоящий парсер языка (например, Babel для JS
или tree-sitter для C++). Он разбирает **текст построчно** регулярными
выражениями. Из этого следуют ограничения:

- Комментарии в середине строки (`x = 1; // комментарий`) считаются кодом,
  а не комментарием.
- Многострочные строковые литералы с символами `{` могут повлиять
