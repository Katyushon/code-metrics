## 1. Что это такое

**CodeMetrics** — расширение для Visual Studio Code, которое анализирует
текущий открытый файл с исходным кодом и показывает его метрики в
отдельной боковой панели.

Плагин работает в реальном времени: как только ты меняешь код, числа в
панели автоматически пересчитываются. Никаких внешних сервисов, никаких
ручных запусков — всё внутри редактора.

**Это не генератор сниппетов и не простая подстановка текста.** Плагин
самостоятельно разбирает код построчно, применяет регулярные выражения,
использует структуры данных (`Map` и стек) и формирует HTML-представление
результата.

---

## 2. Возможности

Плагин считает и отображает следующие метрики:

| Метрика | Что показывает |
|---|---|
| **Всего строк** | Общее число строк в файле |
| **Строк кода** | Строки, содержащие реальный код (без пустых и комментариев) |
| **Комментариев** | Строки, начинающиеся с `//`, `#`, `/*`, `*` |
| **Пустых строк** | Полностью пустые строки |
| **Функций (оценка)** | Количество найденных определений функций |
| **Циклов** | Количество `for`, `while`, `do` |
| **Условий** | Количество `if`, `else`, `switch`, `case` |
| **Макс. вложенность** | Самая глубокая вложенность блоков `{ }` |
| **Частота ключевых слов** | Сколько раз встречаются `if`, `for`, `return`, `class` и др. |

**Дополнительно:**

- Панель с метриками обновляется **автоматически** при редактировании файла.
- Панель автоматически переключается при переходе на другой файл.
- Команда доступна через палитру команд (`Ctrl+Shift+P`).
- Не требует интернета, работает полностью локально.

## 3. Как пользоваться

1. Открой VS Code.
2. Открой любой файл с кодом (`.js`, `.ts`, `.py`, `.java`, `.cpp`).
3. Нажми `Ctrl+Shift+P` (Windows/Linux) или `Cmd+Shift+P` (macOS).
4. Введи: `CodeMetrics: Показать метрики файла`.
5. Нажми Enter.
6. Справа от редактора откроется панель **CodeMetrics** с таблицей метрик.
7. Начни менять код — числа в панели обновятся сами.

Если открыть другой файл и снова выполнить команду — панель уже открыта,
поэтому она просто перефокусируется и покажет метрики нового файла.

**Горячие клавиши по умолчанию не назначены** — это осознанное решение,
чтобы не конфликтовать с другими расширениями. При желании можно
назначить свою комбинацию через `File → Preferences → Keyboard Shortcuts`
и поиск по команде `code-metrics.showMetrics`.

## 4. Что такое «метрики кода»

**Метрика** — это числовой показатель. **Метрики кода** — это числа,
описывающие твой код. Они помогают понять:

- **Не слишком ли файл большой?** Если строк кода больше 300 — обычно
  стоит подумать о разбиении на модули.
- **Достаточно ли комментариев?** Если комментариев 0% при 500 строк —
  код трудно поддерживать.
- **Не слишком ли он сложный?** Большая вложенность (`maxDepth > 5`)
  и много условий (`if` больше 20) — признак запутанной логики.
- **Какие конструкции преобладают?** Много `for` и `while` — алгоритм
  цикличный. Много `return` — вероятно, ранние выходы из функции.

Подобные метрики используются в профессиональных инструментах контроля
качества кода (SonarQube, CodeClimate, ESLint-плагины).

## 5. Поддерживаемые языки

Плагин активируется автоматически при открытии файлов следующих типов:

- JavaScript
- TypeScript
- Python
- Java
- C++

Анализ построен на регулярных выражениях и общих правилах синтаксиса,
поэтому плагин **не привязан жёстко** к одному языку — он корректно
работает и с другими C-подобными языками (C, C#, Kotlin, Go, Rust).

Чтобы добавить новый язык, достаточно дописать его идентификатор в
`package.json` в массив `activationEvents` — код плагина менять не нужно.

## 6. Пример работы

Открой файл `test.cpp`:

```cpp
int main() {
    if (x > 0) {
        for (int i = 0; i < 10; i++) {
            cout << i;
        }
    }
    return 0;
}
```

Выполни команду `CodeMetrics: Показать метрики файла`. Справа появится
панель:

```
CodeMetrics: test.cpp

Метрика                 Значение
─────────────────────────────────
Всего строк             8
Строк кода              8
Комментариев            0
Пустых строк            0
Функций (оценка)        1
Циклов                  1
Условий                 1
Макс. вложенность       3

Частота ключевых слов
─────────────────────
  • int: 2
  • if: 1
  • for: 1
  • return: 1
```

Скриншоты работы плагина смотри в файле `docs.md`.

## 7. Установка из исходников

### 7.1. Требования

- **Node.js** версии 18 или выше
- **npm** версии 9 или выше
- **Visual Studio Code** версии 1.80 или выше
- **Git** (для клонирования репозитория)

Проверить версии:

```bash
node -v
npm -v
code --version
```

### 7.2. Шаги

```bash
# 1. Клонируем репозиторий
git clone https://github.com/ТВОЙ_ЛОГИН/code-metrics.git
cd code-metrics

# 2. Устанавливаем зависимости
npm install

# 3. Компилируем TypeScript в JavaScript
npm run compile

# 4. Открываем проект в VS Code
code .
```

### 7.3. Запуск для отладки

1. В открытом VS Code нажми **F5**.
2. Откроется **новое окно** VS Code — это «хост разработки расширения»
   (Extension Development Host).
3. В нём открой любой файл с кодом.
4. `Ctrl+Shift+P` → `CodeMetrics: Показать метрики файла`.
5. Справа появится панель с метриками.

### 7.4. Обновление при изменении кода

Чтобы VS Code пересобирал плагин при каждом сохранении `.ts`-файла,
запусти в отдельном терминале:

```bash
npm run watch
```

## 9. Как это работает

Архитектура плагина состоит из четырёх слоёв:

**1. Слой точки входа — `activate()`**  
Регистрирует команду `code-metrics.showMetrics` и подписывается на события
VS Code: изменение текста (`onDidChangeTextDocument`) и смену активного
редактора (`onDidChangeActiveTextEditor`).

**2. Слой анализа — `analyzeCode()`**  
Принимает текст файла, разбивает на строки, классифицирует каждую
(код / комментарий / пустая). Считает ключевые слова через
`Map<string, number>`. Вычисляет максимальную вложенность через **стек**:
при встрече `{` — кладём в стек, при `}` — вынимаем, запоминаем максимум.
Возвращает объект `Metrics`.

**3. Слой представления — `buildHtml()`**  
Формирует HTML-страницу с таблицей метрик и списком частотных слов,
отсортированным по убыванию. Возвращает строку с готовым HTML.

**4. Слой отображения — `WebviewPanel` + `updatePanel()`**  
Открывает панель справа от редактора и обновляет её содержимое при
каждом изменении файла.

**Схема потока данных:**

```
editor.document.getText() → текст файла
        │
        ▼
analyzeCode(text) → объект Metrics
        │
        ▼
buildHtml(metrics, fileName) → HTML-строка
        │
        ▼
panel.webview.html = HTML → отображение в панели
```

Подробнее см. [docs.md](docs.md).

## 11. Сборка `.vsix`

Для установки плагина в другие редакторы VS Code можно собрать
устанавливаемый пакет `.vsix`.

```bash
# Установить утилиту vsce
npm install -g vsce

# Собрать пакет
vsce package
```

Получится файл `code-metrics-0.0.1.vsix`. Установить его можно в любую
VS Code через:

**Extensions** → **…** → **Install from VSIX…**

**Важно:** перед сборкой убедись, что в `package.json` указаны поля
`publisher`, `repository` и `license`. Утилита `vsce` требует их наличие.

## 13. Использование ИИ

При разработке данного плагина **использовался ИИ-ассистент** (DeepSeek).
Он применялся для:

- объяснения архитектуры расширений VS Code;
- помощи в написании шаблонного кода (регистрация команды, работа с webview);
- отладки ошибок сборки (`outDir`, `main`, конфигурация TypeScript);
- консультаций по работе с WSL и npm.

**Самостоятельно разработаны:**

- идея плагина CodeMetrics;
- структура данных для анализа (стек для вложенности, `Map` для частот);
- регулярные выражения;
- алгоритм классификации строк и подсчёта метрик;
- формат отображения в webview-панели;
- архитектурное решение о разделении слоёв (анализ / представление /
  отображение).
